Цель:
Перевести командную координацию на GitHub-centered flow, где GitHub остается source of truth для handoff и next-step контекста, а Telegram используется только как notification channel при наличии secrets.

Почему задача нужна:
Сейчас coordination context может теряться между PR, Telegram и handoff заметками. Нужен минимальный, безопасный и воспроизводимый flow, в котором:
- merged PR добавляет запись в один стабильный GitHub coordination log;
- следующий coder начинает работу с GitHub issue и связанных handoff docs;
- Telegram остается только коротким уведомлением и не становится source of truth.

Workflow behavior expected:
1. Trigger on pull_request closed.
2. Continue only when the PR was merged.
3. Read PR metadata and changed files through GitHub APIs.
4. Find the fixed issue titled exactly:
   TEAM COORDINATION LOG — AnalyticsAutomation-Core
5. If the issue exists and is open, comment into it.
6. If the issue exists but is closed, reopen it and comment.
7. If the issue does not exist, create it with the exact title and a short source-of-truth description, then comment.
8. Never create a new issue per PR unless reopening is not possible and a replacement is required.
9. Mark CI/build status as `not evaluated by coordination workflow`.
10. If Telegram secrets exist, send a short notification linking back to GitHub PR and coordination issue.
11. If Telegram secrets are missing, skip notification without failing the workflow.

Comment payload required:
- PR number and title;
- merged commit SHA;
- author;
- labels if available;
- changed areas summary from pull request files API;
- total changed files count;
- contracts, migrations, feature flags, handoff docs and next step from PR body when present;
- PR link;
- CI/build status marked as `not evaluated by coordination workflow`.

Rollback:
- Revert the PR if the automation/comment format is wrong.
- Or disable/remove `.github/workflows/coordination-on-merge.yml`.
- GitHub issue comments remain as audit/history and do not require destructive cleanup.
- No DB rollback.
- No deploy rollback.
