Goal:
Define the approved future runtime work for safe operator-controlled admin password reset/add-admin.

The future runtime work must let an operator on Korobochka either:
- reset or set the password for an existing interactive root/platform admin; or
- create an additional interactive root/platform admin if policy chooses that route.

This must be done without opening public registration and without direct database edits.

This docs-only PR records the future scope and guardrails. It must not implement runtime code.

Context:
S2-51 desktop SignIn runtime is merged and deployed. App.Desktop can show SignIn, accept user-entered credentials, call the existing control-plane sign-in endpoint, and update in-memory desktop session state when credentials are valid.

S2-52 identity bootstrap first-admin task card and runtime are merged and deployed.

Manual bootstrap on Korobochka was attempted after deploy. The bootstrap command returned `status: skipped_existing_admin` for `incident-routing-admin`.

That means a root/platform admin already exists, and S2-52 behaved as an idempotent safe bootstrap path by refusing to overwrite an existing root/platform admin.

Manual desktop SignIn still cannot be completed unless the operator knows a valid password for an interactive root/platform admin account.

This task must not assume the password is known. It must not ask for passwords, tokens, connection strings, or secrets.

The missing capability is not first-admin bootstrap. The missing capability is an operator-approved recovery path for an existing admin password, or an operator-approved path to create an additional interactive root/platform admin.

Open self-registration in App.Desktop is forbidden.

Manual database edits are forbidden.

Secrets must be entered only through operator-local environment variables or a secure interactive prompt. Secrets must never be sent through GitHub, ChatGPT, coordination comments, PR text, reports, screenshots, logs, or committed files.

Future runtime scope:
- Prefer extending `tools/App.Maintenance` rather than App.Api.
- Add an explicit operator-only command such as `identity-admin reset-password`, `identity-admin recover-password`, or `identity-bootstrap set-admin-password`.
- If policy chooses additional-admin creation instead of resetting an existing password, add an explicit operator-only command such as `identity-admin create-root-admin`.
- The exact command names may be chosen by implementation, but the command must be explicit, discoverable, and impossible to confuse with public registration.
- Require an explicit enable flag such as `AA_ADMIN_PASSWORD_RECOVERY_ENABLED=true`.
- Require target login and new password from operator-local environment variables or a secure interactive prompt.
- Never accept passwords as command-line arguments.
- Never print passwords, password hashes, access tokens, refresh tokens, or Authorization headers.
- Redact secret-like values in logs, errors, command output, tests, reports, and PR text.
- Validate that the target account exists for reset-password mode.
- Validate that the target account is an interactive account, not a service/integration account, unless policy explicitly chooses additional-admin creation.
- Validate root/platform-admin assignment policy using existing auth/group admin structures.
- Validate that the account has or will receive the approved `platform_owner` role and root group admin assignment according to existing auth/group-tree rules.
- Use existing password hashing/auth infrastructure.
- Add an audit record/event for every password recovery attempt and result without secrets.
- Ensure idempotent and transactional behavior where database writes are involved.
- Keep the existing `/api/auth/sign-in` contract backward-compatible.
- Support a real manual smoke after merge/deploy through an explicit operator-approved step:
  - run the recovery/add-admin command on Korobochka with operator-local secret input;
  - run App.Desktop against the approved control-plane base address;
  - sign in with the recovered or additional admin account;
  - confirm no password/token/Authorization leakage.
